# OpenWiki 与经验库

## 当前分工

PostgreSQL checkout 中的 `openwiki/` 解释代码机制并维护源码证据。本仓库的 `records/` 保存具体调查、实验和历史决策，`topics/` 提供人工维护的入口。当前只建立本地位置关联，没有统一索引、自动导入或远程刷新任务。

本机源码位置来自不提交的 `knowledge.local.json`。团队成员使用自己的 checkout；技术结论必须说明对应 commit，不能假设所有人的本地代码相同。

## 如何查询

查询现有实现时，先按 PostgreSQL 项目规则使用 OpenWiki 和 CodeGraph。查询过去的排查经验时，在本仓库检索 `records/` 与 `topics/`。涉及某个案例时，读取完整记录并检查适用范围，再核实当前源码。

OpenWiki 不会因为旁边多了一个 Git 仓库就自动检索其中的记录。添加 Markdown 链接也不等于索引了链接目标的全文。

## 后续接入的完成条件

把经验接入 Wiki 时，先确定可以共享的材料范围、Wiki 的维护位置和实际支持的证据路径，再通过 OpenWiki 生命周期更新主题内容。完成后必须实际执行搜索并读取相关章节，确认能找到有用结论及其限制。

现有代码模式的 `repo://` 证据需要位于该 Wiki 的源码仓库中。不要伪造跨仓库路径，也不要为了满足验证机制而把私有对话复制到公开源码仓库。仅能提供阅读链接的材料，应明确作为外部背景，而不是代码实现的证明。

## 共享和刷新

本仓库的 Git 远程提供经验文档共享与版本历史。它不自动发布原 PostgreSQL Wiki，也不会同步上游源码。首个真实案例完成保存、审核和检索验证后，再决定是否增加 Wiki 发布快照或 CI 接入。

定时采集、Wiki 生成、自动提交和发布是不同操作，需要各自明确输入、输出、访问范围与失败处理；创建本仓库不会启用这些操作。
